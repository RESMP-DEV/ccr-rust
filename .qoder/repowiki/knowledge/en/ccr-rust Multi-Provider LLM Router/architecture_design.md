The root Cargo.toml defines a single `ccr-rust` crate whose features (`dashboard`, `gp`, `sindexer`, `telemetry`) gate optional subsystems shared by children. Children are not separate crates — they are modules of this binary: `main_service` bootstraps Axum routes and CLI subcommands, which delegate to `router` for backend tier dispatch (EWMA/GP latency routing with hedging/retries), `transformers` for per-provider format adapters, `core_runtime` for admission/rate-limit/streaming/auth/diagnostics, `metrics` for Prometheus/Redis observability, `mcp_server` for the Model Context Protocol HTTP/stdio entry, and `workers` as an inspection subcommand. Cross-child wiring is centralized in the `main_service` bootstrap plus `build.rs`, while `frontend_adapters` sits between incoming requests and the internal pipeline, and `tests` + `scripts_and_benchmarks` exercise the compiled binary end-to-end; `deploy_infra` ships it via systemd/launchd/Kubernetes.
