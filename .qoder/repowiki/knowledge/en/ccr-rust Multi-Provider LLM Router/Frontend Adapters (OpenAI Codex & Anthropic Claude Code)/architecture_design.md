The module centers on a `Frontend` trait defined in `mod.rs`, which exposes four operations: `name`, `detect`, `parse_request`, and `serialize_response`. Two concrete implementations ship with it — `ClaudeCodeFrontend` in `claude_code.rs` (Anthropic Messages API) and `CodexFrontend` in `codex.rs` (OpenAI Chat Completions / Responses API). Both implement the same trait so the router can dispatch uniformly.

- Shared normalized types live in `mod.rs`: `InternalRequest`/`InternalResponse` bridge both APIs; `Message`, `ContentBlock` (text/image/tool_use/tool_result/thinking), `ImageSource`, `Tool`, and `Usage` are the common vocabulary.
- `detection.rs` provides a lightweight heuristic dispatcher (`detect_frontend`) used before per-front-end parsing: header signals (`anthropic-*` headers, `codex` User-Agent) take priority over body shape heuristics, with Codex as the default fallback.
- Each frontend independently re-implements its own `detect` plus full parse/serialize logic for features specific to that API (e.g. Anthropic `cache_control`/`thinking`, OpenAI `reasoning_blocks`/`developer` role normalization, tool-call ↔ `tool_use` conversion).
- Dependency direction is one-way: frontends depend on the shared types in `mod.rs`; nothing in `mod.rs` depends on the concrete frontends beyond the `pub mod` declarations. Extra provider-specific fields are captured via an `extra_params: Option<Value>` field rather than by extending the core struct.
