Two-layer layout under `src/`:
- `lib.rs` is a flat feature-gated crate root that re-exports every internal subsystem (`admission`, `client_auth`, `config`, `dashboard`, `debug_capture`, `doctor`, `frontend`, `gp_router`, `mcp`, `metrics`, `proxy`, `ratelimit`, `retry_budget`, `router`, `routing`, `schema_validate`, `sse`, `stickiness`, `telemetry`, `transform`, `transformer`, `turn_capture`, `workers`) so downstream crates can depend on the library.
- `main.rs` is the CLI entry point: it defines a `clap` `Parser` + `Subcommand` hierarchy (`Start`, `Status`, `Validate`, `Doctor`, `Workers`, `Dashboard`, `Version`, `ClearStats`, `Mcp`, …), wires Axum `Router` layers (CORS, tracing, body limits), initializes tracing/OpenTelemetry when the `telemetry` feature is enabled, and dispatches to per-feature modules via `mod foo { pub use ccr_rust::foo::*; }` re-exports that mirror the library's public surface. Feature flags gate optional surfaces (`dashboard`, `gp`, `telemetry`).
- `config/` is split into `types.rs` (serde schema definitions — `ConfigFile`, `TransformerEntry`, `ProviderTransformer`, etc.) and `mod.rs` (parsing pipeline: env-reference expansion via `shellexpand`, credential-placeholder detection, provider/client credential validation, listener/port checks). `mod.rs` re-exports `types::*` as its public API, keeping the heavy validation logic behind `pub(crate)`.
Dependency direction is one-way: `main.rs` → `config` → `ccr_rust::*` subsystems; no subsystem imports `main.rs`.
