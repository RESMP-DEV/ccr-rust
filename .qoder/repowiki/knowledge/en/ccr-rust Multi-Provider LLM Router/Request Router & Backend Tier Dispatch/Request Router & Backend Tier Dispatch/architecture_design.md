Two-tier routing architecture:
- `src/routing.rs` provides the default EWMA-latency tracker (`EwmaTracker`) with per-tier smoothing, failure penalties, and stable sort of configured tiers.
- `src/gp_router.rs` implements a Gaussian-process surrogate (`GpSurrogate` from the external `gp_routing` crate) that reranks the EWMA-preferred order using Thompson sampling / UCB acquisition over request features (prompt length, token estimates, time-of-day, stream count, etc.), gated behind the `gp` Cargo feature.
- `src/router/mod.rs` is the Axum handler layer: it exposes `health`, `handle_chat_completions` (OpenAI compat), and `handle_responses`, wires `AppState` (config, trackers, registry, admission/retry budget, sticky sessions, debug capture), runs the selected tier via `execute_attempt` with optional hedging, and streams back translated responses.
- Internal router submodules: `types.rs` defines shared request/response shapes (`AnthropicRequest`, `OpenAIRequest`, `TryRequestError`, `AppState`); `dispatch.rs` performs the actual HTTP call through `try_request`, builds provider-specific headers, applies transformer chains, and handles OpenAI/Responses passthrough; `translate_request.rs` / `translate_response.rs` convert between Anthropic and OpenAI formats; `streaming.rs` abstracts SSE chunk forwarding; `reasoning_controls.rs` normalizes thinking/output-control fields; `responses_api.rs` + `responses_protocol.rs` implement the Responses wire format; `usage_metrics.rs` extracts normalized usage for metrics.
- Dependency direction: handlers → dispatch/streaming/translation → `crate::client_auth`, `crate::transformer`, `crate::ratelimit`, `crate::retry_budget`, `crate::admission`, `crate::metrics`; GP router depends on `gp_routing` and the config module but not on Axum.
