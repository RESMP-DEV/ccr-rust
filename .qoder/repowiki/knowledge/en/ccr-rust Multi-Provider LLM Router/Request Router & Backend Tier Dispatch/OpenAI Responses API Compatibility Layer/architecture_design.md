Entry point `handler.rs` implements an Axum async handler that reads/decompresses the request body, validates it via `responses_request_to_openai_chat_request`, forwards the payload to `crate::router::openai_compat::handle_responses_chat_completions`, then converts the resulting OpenAI JSON or stream response back into Responses format via `convert_openai_json_response_to_responses` / `convert_openai_stream_response_to_responses`. The streaming path is implemented by a stateful `ResponsesStreamConverter` in `incremental_stream.rs` which consumes upstream OpenAI/Anthropic SSE frames once, emits immediate delta events, and defers terminal output-item/response events until `finish()`, using `content_part_events.rs` helpers (`append_content_part_added`, `append_content_part_done`) to build `response.content_part.added/done`, `response.output_text.done`, and `response.refusal.done` SSE frames. Shared conversion utilities (reasoning blocks, usage mapping, output-item identity) live in the parent module and are re-exported via `super::`; the incremental stream delegates content-part emission to `content_part_events` so both streaming and non-streaming paths share the same frame builder. Test modules (`agent_message_tests.rs`, `reasoning_tests.rs`, `request_edge_tests.rs`, `incremental_stream/tests.rs`) cover request validation, reasoning handling, edge cases, and stream parsing independently.
