Two cooperating layers sit behind the `Transformer` trait defined in `src/transformer/mod.rs`:

- `src/transformer/` — runtime layer. `mod.rs` declares the `Transformer` trait (`transform_request`, `transform_response`, `is_passthrough`, `name`) plus a `TransformerChain` and an `IdentityTransformer`. `builtin.rs` holds format-conversion implementations (Anthropic↔OpenAI) and the shared `inject_leading_thinking_blocks` helper used by both this module's `DeepSeekTransformer` and the factory registry.
- `src/transform/` — static provider adapters plus a factory-based registry. Each provider adapter is a separate module (`deepseek.rs`, `glm.rs`, `kimi.rs`, `minimax.rs`, `anthropic.rs`, `anthropic_to_openai.rs`, `openai_to_anthropic.rs`, `maxtoken.rs`, `thinktag.rs`, `toolcompress.rs`, `output_compress/`, `openai_to_anthropic/helpers.rs`). `registry.rs` defines `TransformerRegistry`, a `HashMap<&'static str, Box<dyn Fn(...)>>` mapping config names to factory closures; `new()` registers all built-in providers (zai, minimax, moonshot/kimi, deepseek, longcat-thinking, anthropic, openai-to-anthropic, maxtoken, thinktag, toolcompress, output_compress).

Dependency direction: `transformer/` owns the trait and chain; `transform/` implements concrete transformers and wires them into the registry; `transform/registry.rs` depends on both. Configuration flows through `crate::config::TransformerEntry` into `TransformerRegistry::build` / `build_chain`, which produces a `TransformerChain` of `Arc<dyn Transformer>`.
