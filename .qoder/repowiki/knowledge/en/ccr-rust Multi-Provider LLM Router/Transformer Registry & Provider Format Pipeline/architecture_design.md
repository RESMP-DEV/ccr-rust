The `transformer` crate owns the `Transformer` trait (`transform_request`, `transform_response`, `is_passthrough`, `name`) and a built-in registry (`builtin.rs`) that maps string keys to concrete transformer implementations. The `transform` crate implements each LLM provider's adapter (anthropic, openai, deepseek, glm, kimi, minimax, anthropic_to_openai, openai_to_anthropic) plus cross-cutting transformers (`output_compress`, `toolcompress`, `thinktag`, `maxtoken`). Wiring happens in `transformer/mod.rs`: it re-exports the trait, registers builtins, and pulls in provider-specific transformers from `crate::transform::*`. Shared concerns live at this level: `inject_leading_thinking_blocks` is used by both the built-in `DeepSeekTransformer` and the factory in `crate::transform::deepseek` so construction paths stay in sync, and all children operate on the same `serde_json::Value` contract with Anthropic as the canonical internal format — providers translate to/from it, while output/tool compressors mutate response bodies after translation.
