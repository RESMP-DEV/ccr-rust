Each file under `src/mcp/tools/` implements the `NativeTool` trait defined in `mod.rs`, which exposes two methods: `tools()` returning a list of `McpTool` descriptors and `call(name, arguments)` dispatching to the tool's handler. `ToolRegistry` holds a `Vec<Box<dyn NativeTool>>` and forwards calls by name across all registered tools, returning an error for unknown names. `ToolResult` / `ToolContent` are the canonical JSON-serializable response shape (`content` array with `type`/`text` entries plus an `isError` flag). Tool modules depend inward on `super::protocol::McpTool` and `super::{NativeTool, ToolResult}`; `pyright.rs` additionally delegates workspace path resolution to the private sibling module `pyright_workspace`. The `sindexer` module is gated behind the `sindexer` Cargo feature via `#[cfg(feature = "sindexer")]`. External I/O is isolated per tool: HTTP via `reqwest::Client` (Exa), process spawning + filesystem access (Pyright), and local JSON persistence (MemoryTool uses an atomic temp-file+rename pattern guarded by `parking_lot::RwLock`).
