Three layers compose the module: `protocol.rs` declares MCP message/tool types; `catalog.rs` maintains a per-backend tool registry that maps tool names to `ToolInfo` plus optional compression metadata; `auth.rs` validates Bearer tokens for daemon access. The runtime layer (`server.rs`, `daemon.rs`) exposes two transports — a tokio/axum HTTP endpoint serving native tools and a stdio proxy multiplexing line-delimited JSON-RPC frames to external backend processes. All transports consume the same `protocol` schema and resolve tools through the shared catalog, so adding a new tool means registering it in `tools/mod.rs`'s registry rather than touching transport code.
