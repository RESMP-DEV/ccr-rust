# Qwen DeepSeek-V4.1-Flash-1017 fallback split — 2026-10-19

## Scope

The user observed two Qwen DeepSeek IDs (`deepseek-v4.1-flash-1017` and the
undated `deepseek-v4.1-flash`) and asked that CCR route to the current
checkpoint rather than an older one. This change makes the dated ID the first
DeepSeek fallback and keeps the undated ID as an explicit final fallback. It
does not alter protocol translation, retry semantics, or the Qwen `maxtoken`
fix from the preceding change.

`https://token-plan.maas.qwencloudapi.com/apps/anthropic/v1/messages`,
`sk-sp-` key, `max_tokens:16`, prompt "Reply OK." Each response `model` field

| requested | status | response model |

| `deepseek-v4.1-flash-1017` | 200 | `deepseek-v4.1-flash-1017` |
| `deepseek-v4.1-flash` | 200 | `deepseek-v4.1-flash` |
| `deepseek-v4.1-flash-1016` | 400 | `Model not exist.` |
| `deepseek-v4-pro` | 200 | `deepseek-v4-pro` |
| `deepseek-v4-pro-0813` | 200 | `deepseek-v4-pro-0813` |

Conclusion: Qwen serves the two flash IDs as distinct deployments, each
self-reporting its own ID; they are not silent aliases of one checkpoint. The
`-1016` negative control confirms dated IDs are validated, not accepted
blanket.

## Public model page

Qwen's own model page `www.qwencloud.com/models/deepseek-v4.1-flash-1017`
describes `-1017` as "the latest iteration of V4.1-Flash" (self-feedback RL,
Terminal-Bench 4.0 / DeepSWE v1.1 / ProgramBench gains) and uses
`model="deepseek-v4.1-flash-1017"` in its code sample. The undated page
describes the prior `deepseek-v4.1-flash`. Both share $0.15/$0.60 input/output
per 1M and $0.015 implicit-cache input.

## Chain change

`scripts/ccr_fallback_policy.py` `MACHINE_ROUTE_CHAIN` tail is now
`minimax,MiniMax-M3.1-Flash`, `qwen,deepseek-v4.1-flash-1017`,
`qwen,deepseek-v4.1-flash`. Both dated and undated IDs are added to the Qwen
provider `models` list. No dispatch-side canonicalization was added: unlike
MiniMax, whose dated/preview aliases historically served the *wrong* model,
Qwen already returns the exact requested ID, so a rewrite would only erase the
observable served-model distinction.

## Non-claims

  workload; only that they are distinct served deployments with identical
  published list pricing.

  dated ID that this pin will not follow automatically.
